1. System Architecture

Maintain Ops Suite (MOS) is an integrated operations management platform built on the Nextcloud AppFramework. It provides a unified interface for configuration management, preventive maintenance, deficiency tracking, modernization projects, supply chain control, LOTO/safety management, S1000D technical documentation, and system architecture analysis (FMEA).

Application Model

MOS is a server-side PHP 8.2 application using the Nextcloud AppFramework (QBMapper ORM, Controller/Service pattern). The frontend is a single-page application (SPA) delivered as a single compiled JavaScript bundle (~15,000+ lines). All state changes are persisted to the host database via the Nextcloud QueryBuilder — MOS does not maintain any in-memory state between requests.

App ID: ops_suite. All database tables are prefixed with ops_. Nextcloud's oc_ table prefix applies at the database level — actual table names are oc_ops_assets, oc_ops_procedures, etc.

Request Flow

Browser → Nextcloud CSRF Gate → AppFramework Router
    → Controller (permission check) → Service / Mapper
    → IQueryBuilder → Database → DataResponse (JSON)

4. Asset Code Structure & Field Definitions

The asset_code field provides a human-readable, structured identifier for each configuration item. It is separate from the system-assigned id (auto-increment) and asset_id_label (formatted ASSET-NNNN).

Recommended Format

{SITE}-{TYPE}-{SEQ}

Example: PLT1-GEN-001
FieldLengthDescriptionExamples
SITE2–4 charsSite or platform identifierPLT1, SITE, BLDG
TYPE2–6 charsEquipment type abbreviationGEN, UPS, RTR, SW, HVAC, PMP, SRV
SEQ3 digitsZero-padded sequence within type at site001, 002, 012

Key Asset Fields

FieldTypeNotes
idBIGINTSystem-assigned numeric PK. Never changes.
asset_id_labelVARCHARDisplay label ASSET-{NNNN}. Auto-generated. Used in DMC construction.
asset_codeVARCHARUser-defined structured code. Basis for DMC generation.
nameVARCHARHuman-readable equipment name.
asset_typeENUMhardware | software | firmware | infrastructure | vehicle | facility
statusENUMoperational | degraded | offline | decommissioned | spare
serial_numberVARCHARManufacturer serial number — primary IUID/UII reference.
criticality_codeCHAR(2)CR Critical | DE Degraded | RD Redundant | SP Spare | AD Administrative
last_verified_atDATEDate of last physical verification. Flagged overdue at 18 months.
tdp_source_asset_idBIGINTReferences another asset's TDP folder. Use for identical equipment sharing documentation.
platform_idBIGINTPlatform scoping. Null = visible to all platforms (admins only).
For DoD compliance: the serial_number + manufacturer + model triplet forms the basis for Unique Item Identifier (UII) construction per MIL-STD-130. The iuid_compliant flag tracks whether the physical item has been marked with a compliant 2D data matrix label.

7. Platform, Group & Role Access Model

MOS uses Nextcloud's group-based access control. Each role is mapped to a Nextcloud group in Settings. The system resolves the user's effective role at API call time via PermissionService.

Logistics CoordinatorPlatformWrite for supply requests and inventory.

S1000D Library Access

The Library uses a two-level gate. canWrite() (cached per session) returns true for any role with general write access. Technicians and Read Only users land on the IETM viewer by default. The Builder tab (DM authoring and publication assembly) is only visible when canWrite() returns true.

Nextcloud administrators always receive Administrator access regardless of group configuration.

8. PM Scheduling Logic & Due Date Calculation

The PM module calculates next_due automatically from last_completed and periodicity. Overdue status is derived by comparing next_due to the current date at query time.

Periodicity → next_due Calculation

PeriodicityFormula
dailylast_completed + 1 day
weeklylast_completed + 7 days
monthlylast_completed + 1 calendar month
quarterlylast_completed + 3 calendar months
semi_annuallast_completed + 6 calendar months
annuallast_completed + 12 calendar months

Additional Logic

Overdue: next_due < TODAY(). Dashboard Readiness tile counts overdue PMs. SEV-1/SEV-2 open deficiencies elevate urgency display.

Auto-Deficiency on Fail: If create_deficiency_on_fail = 1 on a PM, the system automatically opens a linked deficiency when the PM closeout result is set to Fail. The deficiency inherits asset_id and is assigned to the same technician.

DM Review Flag: When a linked 200/720/730 DM advances its issue number, dmc_review_flag is set on the PM. A banner prompts the technician to review the updated procedure before completing the next PM. The flag clears on next PM completion.

Severity Definitions

CodeNameDefinition
SEV-1Mission CriticalAsset non-operational. Immediate corrective action required. All resources prioritized.

SEV-3ModerateAsset operational. Deficiency requires scheduled corrective action within the next maintenance window.

Status Workflow

StatusDescription
openInitial state when deficiency is logged.
in_workActively being investigated or corrected.
waiting_partsCorrective action identified; awaiting parts from supply.
waiting_approvalCorrective action pending CCB or management authorization.
closedDeficiency resolved. All closeout fields required.

Closeout Requirements

Closing a deficiency requires all of the following fields to be populated: root_cause, corrective_action, actual_parts_cost, actual_labor_cost, actual_man_days, and reviewed_by. The system records closed_by and closed_at automatically on status transition to closed.

SRFQ Numbering

Supply RFQ numbers auto-generate as SRFQ-YYYY-NNN (year + 3-digit zero-padded sequence, resetting annually per platform). The RFQ export includes: line items, NSN, CAGE code, quantity, unit of measure, estimated cost, terms and conditions, and authorized signature blocks.

Cycle Count Classification

ClassCriteriaCount Frequency
AHigh-value or high-turnover itemsMonthly
BMedium-value or medium-turnover itemsQuarterly
CLow-value, low-movement itemsAnnual

Quarterly Revalidation

Open requisitions with no activity for 90+ days are flagged with revalidation_required = true. A banner appears on the requisition requiring the logistics coordinator to confirm the requirement is still active or cancel the requisition to prevent stale open orders.

12. API Conventions

All MOS APIs follow RESTful conventions routed through Nextcloud AppFramework. All requests require a valid Nextcloud session and a CSRF token (requesttoken header) on mutating operations.

URL Patterns

GET    /apps/ops_suite/api/{resource}          — list
GET    /apps/ops_suite/api/{resource}/{id}      — show
POST   /apps/ops_suite/api/{resource}           — create
PUT    /apps/ops_suite/api/{resource}/{id}      — update
DELETE /apps/ops_suite/api/{resource}/{id}      — destroy

Response Format

All responses return JSON. Success responses are 200 (GET, PUT), 201 (POST), or 204 (DELETE). Error responses include a message field. Standard HTTP error codes: 400 (bad request), 403 (forbidden), 404 (not found), 500 (server error).
